# Pilot 001 — Does shared GitHub memory improve research handoffs?

**Status:** Proposed, 17 November 2026. Access preflight completed. Comparative runs pending.

## Question and prediction

Does access to a frozen Future Farm repository improve an independent agent's recovery of earlier findings, corrections, and disagreements while preserving its ability to challenge them? This pilot tests one handoff on one case. It cannot establish that the architecture works across topics, long chains of agents, or unrestricted tools.

## Four short research runs and one independent review

1. Before any run, freeze a common task, an identical packet of checked primary research or authoritative excerpts, the scoring key, and the repository revision. Start with `eda50005a77b7465990e8a72c22aeb4bc54dc696` (the `main` ref observed during preflight). Resolve the files by SHA and verify all candidate anchors against that revision. Fix the session limits, output limit, packet contents, and scoring key before collecting answers. Record the packet and key hashes.
2. Use two model/tool configurations, one of them Codex. For each configuration, run one fresh session with the frozen repository available via read-only GitHub retrieval and one fresh session without GitHub access. Randomize run order within each configuration and record it. Disable conversation history, personalization, and general web retrieval for all four runs. Both arms get identical scientific evidence and a neutral common prompt. Only the memory arm gets the repository coordinates and instructions to follow README and AGENTS. Restrict GitHub reads to the frozen revision, so neither arm encounters this protocol, the scoring key, or prior outputs. Verify actual tool access and log any deviations. If a platform cannot enforce the isolation, record that run as ineligible for the paired comparison.
3. Use the same task and answer format for every run. Ask for an evidence brief on whether changing when and where apple resources are available could support fruit-feeding insects and decomposers while sustaining fruit production and tree health. Ask for prior claims and corrections if recoverable, evidence for and against a specific proposal, any disagreement and its consequence, the agent's own inference with confidence, and one observation that would change that inference. Keep the brief to 600 words and give each session the same 15-minute limit. Log retrieval calls and elapsed time. Record configuration and model identifiers where exposed.
4. Collect all answers before showing anyone the scoring key or prior runs. Give a scorer randomized labels and withhold the assignment and configuration metadata until scores are frozen. Citations may reveal the condition, so record suspected assignments and describe this as assignment masking. Ask a separate fresh agent to replay one substantive inference from each arm per configuration using the cited materials, the same packet, and the frozen repository when cited. Supply the selected claim and reasoning without the original score. Have the reviewer record traceable reproduction, a traceable challenge, or inability to reconstruct the claim, with citations and reasons.

## Scoring

Freeze a four-item recovery key with file and section anchors before launch. Candidate anchors are in the November 17 correction record and the apple case study. Include at least one recorded scientific mechanism or prior finding and one attributed correction. Candidate content includes the codling moth feedback, the scope of the correction, the status of the illustrative percentages, and the distinction among insect species and substrates. Check that the final key includes an actual previous finding or clearly labels it a previously recorded mechanism; do not elevate a project assertion to primary evidence.

| Measure | Scoring rule |
|---|---|
| Historical recovery (0–4) | One point per correctly recovered item with a resolvable repository anchor and accurate evidence status. Also report uncited conceptual matches separately, so a good independent answer can receive credit on its substance. |
| Attribution (0–2) | One point for consistently marking prior positions and sources or explicitly reporting unavailable provenance. One for clearly identifying the current agent's own inference and premises. |
| Contradiction handling (0–2) | One point for identifying the incompatible readings or scope dispute and their sources. One for explaining the consequence and leaving any remaining empirical dispute open. Score against a documented dispute in a common evidence item or common task fixture, so both arms can earn points. Label any synthetic fixture and keep it out of the historical recovery key. |
| Independent scientific judgment (0–3) | One point for correctly representing common evidence, including its limits. One for a specific, supported counterargument or rival mechanism. One for a discriminating observation and stated uncertainty. |
| Reproducibility and challenge | For each selected inference, record whether a fresh reviewer can trace the premises and reproduce the inference or make a cited challenge. Agreement is unnecessary. Record which source or step blocks a failed replay. |
| Preservation | Check the contribution diff against the base. Pass if each output and all critiques and adjudications have separate stable entries, corrections link to what they correct, and the original source files and original run outputs remain intact. |

The pilot supports the prediction only if both matched memory runs recover at least two more historical items than their controls, neither scores lower on independent scientific judgment, at least one inference from each memory run is reproducible or traceably challenged, and the preservation check passes. Report every score, including attribution and contradiction handling, and publish both paired differences. Treat a qualified run that misses any criterion as failing the pilot prediction. Treat a compromised or incomplete comparison as inconclusive. Report how often the content was recovered without exact provenance, since the primary measure rewards access to historical sources by design. Four runs provide a feasibility signal, with no population effect estimate or statistical significance claim.

## Results record

After the runs, submit a new PR adding `results/shared-memory-pilot-001/` with the dated protocol reference, task and permitted evidence packet or exact archived citations, the frozen key, assignment log, original briefs, access/tool logs, scored rubrics, and independent reviews. Publish each correction or labeling change as a separate entry linked to the affected run. Include a result summary covering paired scores, time and tool errors, source gaps, contamination, reviewer disagreements, and the preservation check. Keep the key and run materials away from participants until their outputs are sealed. Only include material approved for the public repository.

### Preflight observation — participant 001

Codex, using the GitHub connector and the existing conversation, successfully retrieved all 11 tracked Markdown files on `main` during the initial access check. In the protocol preparation session it again retrieved both startup files and the relevant foundation, correction, protocol, and case-study files. The correction record preserves the objection about future codling moth pressure and the correction about what that feedback can establish. Its account is labeled a reconstruction. This establishes retrieval in this environment only. Codex's existing context and exposure to the rubric make this session ineligible as a blinded participant run. No baseline, scoring, comparison, or independent replay has been completed.
